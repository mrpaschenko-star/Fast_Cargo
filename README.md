Диаграммы и печатные страницы открываются без Java и доступа к GitHub.

## Ключевые решения

1. WAL-based CDC с отдельной реплики: включая bootstrap и служебные запросы, без SELECT на основной БД и без изменения исходников легаси в M1–M3.
2. Strangler Fig, Database-per-Service, Saga и outbox/inbox: локальные транзакции, контролируемые повторы и независимые релизы.
3. Физическое разделение профилей и платежей; CRM читает историю через API, PAN передаётся непосредственно провайдеру через redirect.
4. Отдельный контур телематики: отказ склада или биллинга не блокирует фиксацию координат и приём заказов.
5. Проверяемые KPI и поэтапное переключение; экономический эффект рассчитывается по фактической марже и TCO.

## Условия, которые нельзя считать уже выполненными

- Версия PostgreSQL и инфраструктура не даны. CDC с реплики требует проверки совместимости и безопасной настройки на неделях 1–2; переход на primary SELECT не является резервным вариантом.
- UUID не делает данные анонимными. Требование передавать каждый связанный статус заказа за ≤5 с может конфликтовать с внешним обезличиванием; нужен утверждённый контракт данных и решение ИБ, без скрытого ослабления SLA.
- Точный SLA EDI, бюджет, объёмы истории, состав команд и сроки хранения отсутствуют в кейсе. Предлагаемые значения отмечены; окупаемость и соответствие законодательству не объявляются доказанными.

Это выполненная проектная работа, а не внедрённая система. Нагрузочные/аварийные испытания описаны, но на инфраструктуре Fast Cargo не проводились. [Источники](sources/README.md).
